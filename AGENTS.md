# FF — Shorts production (source of truth)

**Trigger:** In the ChatGPT project FF, requests like «Создай видео», «Следующий ролик», «FF, ролик про…». Default to selecting a topic autonomously. This file is the **only authoritative workflow and style contract**. Do not copy it into the ChatGPT Project instruction or the Skill.

**Deliverable:** a real vertical 9:16 MP4 with **intelligible neural narration** (Russian by default; English is allowed when chosen explicitly for the episode), coherent generated imagery, animated motion graphics, infographic, and sound design, returned **in this chat**. Images, storyboards, silent slideshow videos, or a promise to render later do not satisfy the request.

## Production loop

1. **Discover + verify.** Select a surprising, immediately visualizable, harmless fact with a strong contradiction/question for the first second. Verify with at least two independently hosted credible sources, ideally primary research. Record exact numbers, units, qualifiers, links and uncertainties. Reject facts that cannot be demonstrated accurately in 15–25 seconds; never trade factual accuracy for a hook.
2. **Write + direct.** Produce a 15–25-second spoken script (roughly 35–55 Russian words or an English equivalent): a concrete hook in the first 1–2 seconds → visual evidence → twist/payoff that rewards the viewer. Plan 5–8 shots. For **every shot**, record duration, narration, exact `onscreen_text`, `visual_asset` (asset path/ID), `visual_intent` (what the viewer learns), `motion_cue` (specific meaningful object change), evidence link, and the change synchronized with the spoken line. Reject shots that merely animate decoratively. Put the qualifier next to a potentially misleading claim, not in tiny footnotes.
3. **Make assets.** Generate a coherent set of **text-free** hero images, close-ups and backgrounds; three or more shots need genuinely different subject matter, not re-crops of one collage. Keep exact numbers, text and diagrams as code-drawn overlays. Validate physical direction, proportions and diagrams before rendering; no plausible-looking but wrong or ambiguous arrows. Avoid unexplained particles, false progress indicators and generic motion that competes with the fact.
4. **Narrate + mix.** Use a **natural neural voice**, Russian by default or English if chosen for the episode. Preferred no-key CLI: `python -m scripts.voice manifest.json --output voice.wav` (Edge TTS, online). It creates `voice.voice.json` with a transcript checksum. Another approved neural provider is allowed if its output has equivalent receipt metadata; **never substitute eSpeak, monotone system TTS, silence or unrelated music**. Allow 150 ms lead-in and 100 ms tail per shot; change scene timings if speech doesn't fit. Mix narration prominently above subtle music/SFX, without clipping. Audition the entire spoken track or verify intelligibility against an ASR transcription **and** listen to questionable segments. Edge TTS is an unofficial external service: network failures or upstream changes block release, not trigger a robotic fallback.
5. **Compose + animate.** Use the repository's shared scripts (`scripts/render.py` for deterministic layers and `scripts/voice.py` for speech); do **not** recreate a large throwaway `build.py` that escapes tests. More capable video tools may replace individual shot generation, but their files and timings still belong in the same manifest and QA. All onscreen text must render inside explicit bounding boxes: >=8% left/right, >=12% top and <=80% bottom for important editorial content. Measure final pixel extents for each draw; wrap/shrink or fail rather than clip. Maintain one focal object and evidence-driven motion per shot. Export H.264/yuv420p/AAC vertical MP4 (default 720×1280 at 24/30 fps) into `/mnt/data`.
6. **Inspect + repair.** Run `python -m scripts.qa manifest.json --video final.mp4 --voice voice.wav --receipt voice.voice.json --review review.json --report qa.json` as a **required release gate**. It validates metadata, every decoded frame for blank/frozen frames, timeline, levels, narration checksum, source independence and the complete semantic review. Agent must additionally view all shots at start/mid/end and at least 1 frame/second, listen to the complete video, inspect title/caption bounds against the Shorts safe area, and check the physical meaning of diagrams and transitions. A passing automated check is **not** proof of intelligible voice, true claims or artifact-free imagery. Set `review.json` keys to true only after directly checking: `speech_understandable`, `facts_verified`, `motion_matches_narration`, `no_visual_artifacts`, `text_inside_safe_areas`, `hook_is_immediate`, `pace_and_ending_work`. On any failure, repair specifically and rerun. At most two repair passes, then report a blocker instead of claiming success.
7. **Deliver only if QA passes.** Link a playable `sandbox:/mnt/data/*.mp4` in chat, give duration, voice language/provider, and any honestly unresolved subjective limitations. Never publish without approval, never charge without approval and never edit the repo during routine episode creation unless asked. A finished MP4 alone is not a successful episode if narration is incomprehensible or facts/graphics are wrong.

## Repeatability and audience-quality contract

- **Single manifest:** use explicit `language`, `sources` (two independent domains), and 5–8 `scenes` with `duration`, `narration`, `onscreen_text`, `visual_intent`, `motion_cue`, `visual_asset`, and source/evidence. Require at least three distinct visual assets. Keep final script, audio receipt, version identifiers, render command, QA report and `review.json` together per episode. If an agent uses an alternative renderer, its text geometry must be audited just as strictly.
- **Release is fail-closed:** no neural speech/receipt, no proof source, inadequate visuals, misleading animation, offscreen text, unreviewed voice, or failed QA means **no final video**. Demo `examples/wombat.json` and silence are not release-eligible. Do not auto-mark quality review fields true from a successful render alone.
- **Performance is learned, not promised:** before editing, write a one-sentence audience promise and a clear visual hook. Remove intros, filler, repeated images, gratuitous charts, needlessly repeated text and unfounded surprises. After authorized publication, use actual YouTube Studio metrics (viewed versus swiped away, early retention, completion/replays, shares and subscriptions per impression) to propose **one measurable creative change** per subsequent episode. Do not invent analytics or guarantee a view count, including a million views.
- **Tool realism:** GitHub contains code and CI but cannot by itself grant network access, run a command in an inaccessible chat container, or create quality narration. Edge TTS requires online access and may break; use an available, permitted neural provider or report a blocker. Never present an untested integration as working.

## Channel art direction

**Brand:** bright, memorable and friendly; premium playful 2D/3D editorial motion, not noisy clickbait. Cohesive across episodes but each fact gets its own expressive subject and fresh scenes.

- **Palette:** primary blue `#2386F8`, deep navy `#101C35`, warm white `#FFFDF5`; highlights yellow `#FFE352` and occasional coral `#FF7966`. Use no more than two accents per scene; prioritize contrast and legibility over saturation.
- **Typography:** one geometric sans family (e.g. Manrope/Inter, with a Cyrillic-capable fallback), two weights, kinetic emphasis on key words. Copy is short; headings ideally up to two lines. Do not repeat a huge header in every shot. Avoid rough brush fonts and fake AI-generated lettering.
- **Composition:** one focal subject and one clear text hierarchy per shot. Reserve roughly 8% horizontal margins, 12% at top and 20% at bottom for Shorts UI. Text must fit *within* its allocated safe box; shrink/reflow or move it away from the subject rather than cropping or overlapping. Apply a subtle contrast scrim/plate over busy imagery. Keep diagrams schematic, correct and readable.
- **Motion:** intentional camera parallax, object transitions, animated diagrams and responsive typography. Introduce new visual meaning about every 1–2 seconds but avoid strobing, constant random zooms, excess noise and rapid flashing. Infographics should explain rather than decorate.
- **Consistency:** same design tokens, type scale, motion easing, illustration/render treatment and sound palette in one video; retain the same character/model where a character recurs.

## Files and limits

- Read this file on each new FF session from `tim8es/ff`; load only files relevant to the run. Do **not** read every file in the repository by default.
- `skills/ff-shorts/SKILL.md` is a discovery pointer, not duplicate instructions.
- `examples/wombat.json` is a structural/demo example, **not** final visual quality.
- `scripts/render.py` is a reusable compositor, **not** an image/video generator or TTS service.
- Store per-video script, source list, scene manifest and asset paths together for reproducibility. Do not commit generated footage/assets by default.
- A ChatGPT Project router can request these steps but cannot make unavailable video/TTS tools appear. If a tool, budget or render is blocked, state the exact limitation; **never** present an image sequence as the requested finished video.
