# FF: голос с iPhone и монтаж без пустых пауз

## Почему прежние ролики звучали монотонно

Qwen3-TTS **не обучается заново** на твоём референсе: модель использует короткую запись и точную расшифровку для zero-shot клонирования. Шум, эхо и небрежные речевые паузы могут ухудшить похожесть и естественность, но шум от референса **не обязательно** дословно воспроизводится в генерации. Качество нужно оценивать A/B на одном тексте, одинаковой модели и с одинаковыми настройками. Увеличение размера модели само по себе не лечит некачественный материал.

В старой сценовой склейке `compose_timeline` каждое высказывание начиналось примерно через 150 мс после начала кадра, а оставшееся до заданной длительности сцены время заполнялось тишиной. Это создавало неестественные длинные паузы. Текущий режим `pacing="tight"` измеряет **фактическую речь**, убирает только тишину по краям реплик, оставляет в среднем 140 мс перехода и обновляет длительности сцен. Речь не ускоряется. Применяется к новым owner-видео; старый режим сохранён для обратной совместимости.

## Как записать лучший референс на iPhone

1. Тихая комната с мягкими шторами/одеялами; выключить вентилятор, телевизор, уведомления. Не записывать рядом с улицей.
2. Держать iPhone примерно в **15–25 см от рта**, чуть сбоку от потока дыхания, без прикосновений к корпусу во время записи. Не двигать телефон, держать одинаковое расстояние.
3. Записать **2–4 минуты** разнообразной русской речи с вопросами, короткими и длинными предложениями, паузами и эмоциями без актёрского переигрывания. Отдельно можно записать 1–2 минуты английского, если важна английская речь.
4. Не читать заученно и монотонно. Оставить 3–5 секунд тишины до/после каждой записи для оценки шума комнаты. Запись `.m4a` из «Диктофона» подходит в качестве исходника.
5. Для Qwen выбрать непрерывный **чистый отрезок 5–25 секунд**; максимум 30 секунд. Его точная расшифровка должна совпадать с произнесённым текстом, включая слова-паразиты и фактические пропуски. Не менять транскрипт после обрезки аудио.

## Локальная подготовка без передачи звука в облако

```bash
python -m pip install -r scripts/requirements.txt
python -m scripts.audio_refine \
  --input "/private/iphone.m4a" --output "/private/clean.wav" \
  --start 1.08 --duration 25 --reduction 0.50 \
  --report "/private/audio_refine.json"
```

Указанные `start`/`duration` — **пример**, а не универсальные параметры. Обязательно выбери границы целых фраз, не отрезая слоги. Фильтр: high-pass 75 Гц, лёгкая стационарная спектральная маска с сохранением части шумового фона, выравнивание уровня с пиком ниже −3 dBFS. Не применяется изменение частоты основного тона, pitch correction или искусственная «студийная реверберация». Сравни исходник с выровненной громкостью и обработанную версию на слух. При металлических артефактах снижай `--reduction` до `0.25–0.35` или отключай её (`0`).

`scripts.production` по умолчанию выполняет ту же осторожную очистку после **приватной расшифровки** reference.bundle на runner. Для уже профессионально обработанного референса укажи `tts.reference_preprocessing: "none"`, чтобы не фильтровать запись дважды.

## Монтаж и проверка содержания

Каждый выпуск с профилем `ff_owner` обязан указать в пяти–восьми сценах:
`beat: hook|setup|proof|pivot|payoff`, точный `narration`, `visual_asset`, `visual_intent` и `motion_cue`. Первый хук ≤ 4 секунд, финал — payoff. `scripts.story_contract.validate_story` отклонит отсутствующий сюжетный каркас, но не оценивает интересность факта и не заменяет проверку фактов.

`scripts.pacing.compose_tight` сохраняет **внутренние интонационные паузы**, убирает только длинную тишину до/после реплики, мягко гасит границы (12 мс), вставляет короткий промежуток между сценами и пишет реальные `scene_durations` в WAV receipt; они переносятся в итоговый манифест. Если фраза длится слишком долго для одной сцены (>9 секунд), она не ускоряется — сборка останавливается и требует переписать реплику.

## Важное действие безопасности

Ранее в публичном `main` был обнаружен файл `.private_voice/FF_VOICE_BUNDLE_KEY.txt`. Он удалён коммитом `c0d8a3a`, но может остаться в истории Git. **Владелец репозитория должен заменить секрет `FF_VOICE_BUNDLE_KEY` в GitHub Actions и повторно зашифровать референс новым ключом**. До ротации старые зашифрованные пакеты нельзя считать защищёнными. Новый личный голос нельзя добавлять в публичные ветки, даже зашифрованным старым ключом. `.gitignore` и CI-тест лишь предотвращают новые случайные коммиты, не удаляют данные из истории.
